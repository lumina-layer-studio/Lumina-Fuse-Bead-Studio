# 3D 划过即放置与落豆动画设计

## 目标

在 3D 编辑模式中，画笔或橡皮划过格子后，下一帧就显示结果，不再等鼠标松开或精确融合模型生成完毕。精确压合轮廓仍在后台收敛，打印 SVG、尺寸和交接数据保持不变。

本轮只处理 3D 画笔/橡皮的即时反馈与放置动画；压合程度、不规则挤压和单豆节距的 2D/3D 动态调节另行实现。

## 用户可见行为

- 画笔按下即放置首颗豆子，按住划过时逐格显示；鼠标松开只结束这一笔，不再触发补放。
- 橡皮划过时立即隐藏目标豆子，不播放落豆动画。
- 填充、区域擦除和吸管继续保持单击工具语义。
- 编辑模式的左键/单指用于工具；视角模式、右键、Alt+左键、中键和滚轮的相机操作保持不变。
- 相机、豆板、定位柱和 WebGL 画布在编辑过程中不重建、不跳回默认视角。
- 4096 颗豆的现有 3D 安全上限和 WebGL 失败后的 2D 降级保持不变。

## 放置动画

新放置的豆子使用已确认的 ABC 混合动作，总时长约 370ms：

1. `0–80ms`：快速显形和缩放，确保划过后立即有反馈。
2. `80–270ms`：从豆板上方快速落到定位柱。
3. `270–370ms`：一次很小的回弹后定型，不做连续弹跳。

连续划过时，每颗新豆按进入格子的时间独立启动动画。既有豆子、重新着色的豆子和后台精确模型切换不得重复播放动画。系统开启 `prefers-reduced-motion: reduce` 时取消位移和回弹，直接显示最终姿态。

## 浏览器端渲染结构

全部逻辑运行在用户浏览器中，不新增后端接口。

3D 控制器保留现有精确融合表面，同时新增一个常驻的快速实例层：

- 快速层使用一个固定容量的 `InstancedMesh`，每个格子对应稳定实例槽位；空格以零缩放隐藏。
- React 项目状态变化后，在 `useLayoutEffect` 中把最新项目交给控制器；控制器通过单个 `requestAnimationFrame` 合并同一帧内的更新。
- 新增豆、删豆和改色只更新受影响实例的矩阵与颜色，不创建新的 renderer、scene、camera、material 或 Worker。
- 压合外径、孔径、厚度和不规则偏移复用现有规范公式。快速层只近似颜色边界融合与四豆交汇凹点，不退化成普通圆柱或像素块。
- 快速层出现时暂时隐藏旧精确表面，避免删除后旧豆仍露出；最新精确结果完成后，在同一帧原子切回精确表面。
- 精确融合继续使用现有 Worker 的“最多一个在途、只保留最新待处理”规则。过期结果不能覆盖最新快速层，也不能重置相机。

首次进入 3D 时，快速层先建立逻辑网格和拾取尺寸，因此用户不必等待首次精确表面完成就能编辑。

## 动画状态与性能

动画状态保存在控制器的实例槽位元数据中，不为每颗豆创建 React state。只有存在活动动画、相机变化或待上传实例时才请求下一帧。

验收预算：

- 指针进入新格到快速层可见：下一动画帧，目标 P95 小于 32ms。
- 单次格子更新不创建 Worker、不解析 SVG、不分配或销毁整批几何。
- 64×69 测试图连续划过时，主线程不出现超过 50ms 的新增长任务。
- 精确模型在后台生成期间，快速画面持续可见且可继续编辑。

## 验证

- 组件测试：按下即放置、跨格拖动、同格去重、松开不补放；三个单击工具语义不变。
- 控制器测试：快速层实例增删/改色、动画时序、旧精确表面隐藏、最新精确结果原子接管。
- 稳定性测试：连续项目更新只复用一个控制器、一个快速网格和一个 Worker；相机姿态保持；过期结果不回写。
- 资源测试：卸载或 WebGL context loss 时取消动画帧并仅释放一次快速层 geometry、material 和 mesh。
- 无障碍测试：减少动态效果设置生效，编辑/视角模式与现有键鼠提示不回归。
- 真实浏览器测试：在复杂图纸上连续画笔与橡皮划动，检查即时反馈、动画手感、撤销以及精确模型最终一致性。

## 不变项

项目数据格式、撤销语义、精确 SVG 指纹、成品尺寸、压合厚度、材料映射和 Lumina 交接协议均不改变。
